# Инструмент диаграмм классов UML: модель пишет агент, раскладку правит человек

## Проблема

На предмете «Проектирование архитектуры информационных систем» нужно рисовать диаграммы классов UML. У PlantUML и Mermaid запутанная раскладка, вмешаться в неё почти нельзя, и агент не может сделать аккуратнее. В drawio формат слишком свободный: агент «наворачивает» (например, диаграмма не видна в тёмной теме).

## Решение

Термины — по `GLOSSARY.md`, выбор формата — в `docs/adr/0001-yaml-as-diagram-format.md`.

- Диаграмма лежит в одном файле `*.cd.yaml` (строгий YAML по JSON Schema) и состоит из модели (`classes`, `relations`, её пишет агент) и необязательной раскладки (`layout`, её правит человек в редакторе).
- Оформления в файле нет: диаграмма чёрно-белая, тему выбирает только рендерер.
- Детерминированная автораскладка расставляет всё, чего нет в раскладке. Закреплённые классы не двигаются.
- Для агента: `diagent schema`, `diagent check [--json]`, `diagent render`, `SKILL.md`. Для человека: `diagent edit`, веб-редактор раскладки.
- Стек: TypeScript целиком, `elkjs` (ELK Layered), пакет `yaml`, публикация в npm (`npx diagent`). Интерфейс на английском, содержимое диаграмм на любом языке.

## Порядок

1. Схема и `check`: агент может писать валидные диаграммы.
2. Автораскладка и `render`: PlantUML больше не нужен.
3. Редактор раскладки.

## Вне первой версии

Другие виды диаграмм UML, пакеты, заметки, классы-ассоциации, n-арные ассоциации, шаблонные параметры как структура, правка модели в редакторе, PDF.

## Эталон

Диаграмма Колобка (`kolobok-plantuml.png` рядом с тикетом): около 20 классов, все виды связей, самоассоциация, две связи между одной парой классов. Её вид в PlantUML — то, хуже чего быть нельзя.
